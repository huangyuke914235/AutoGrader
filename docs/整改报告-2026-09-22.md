# AutoGrader 整改结果（2026-09-22，对照《深度审查与整改执行清单》）

> 说明：清单里的基线数字（MAE 13.33 / 22.2% / 95.1%）**已经过期**。
> 在本次整改之前，同一天已经完成了两轮修复与复测，实际指标是
> **修复前 20.44 / 0% / 84.9%，修复后 7.56 / 33.3% / 93.0%**。
> 本报告的整改**没有**以提高指标为目的，其中若干改动（例如强制 miss = 0 分、
> 系统错误不再算作失分）反而可能让分数分布发生变化——这一点在"验证结果"里如实说明。

## 已完成

### P0-1 证据校验闭环

- 问题：两次引用失败后在旧对象上改字段，无效 evidence 被保留、`char_start = -1`；`miss` 可携带证据绕过校验。
- 根因：没有统一的规范化入口，多个分支各写各的。
- 修改：新增 `pipeline.degrade_for_evidence_failure()` 生成**干净的新对象**；`verify_evidence` 对 `miss` 强制 `score=0` 且 `evidence=[]`；新增 `llm.normalize_judgement()` 作为唯一规范化入口；只对通过校验的引用做 `locate`；引用长度设上下限（6~200 字）。
- 测试：`tests/test_evidence.py` 10 项（含"miss+正分+伪造证据"、"两次伪引用"、"降级对象干净"）。

### P0-2 低置信可靠交给人

- 问题：只有两次 verdict 不同才标记；复核异常被静默忽略；分数差距不检测。
- 修改：置信度低于阈值**无论二次是否相同**都标记；复核异常写进 `reason` 并标记；二次结果走与首次相同的数据+证据校验；新增 `score_gap` 阈值（默认该点满分 25%）；明确写死"二次结果只用于风险标记，不改分数"。
- 测试：`tests/test_pipeline.py` 5 项。

### P0-3 人工覆盖真正生效

- 问题：数字框改了只显示警告，不进结果、不改总分、不影响导出、理由非必填。
- 修改：新增 `HumanOverride` 模型；新增"应用改分"按钮；分数变化时理由必填；应用后重算总分并落盘；**保留 AI 原始分**（`ai_total`）；导出同时给出 AI 得分与最终得分、改分理由、系统错误；导出逻辑抽成 `pipeline.build_export_rows()` 以便测试。
- 测试：`test_override_changes_total_and_keeps_ai_total`、`test_export_rows_contains_override_and_ai_score`。

### P0-4 Rubric 约束

- 问题：13 项输入会先归一再截断，得到 12 项合计 92.3 分；id 重复/空、负分、NaN 未拦截。
- 修改：`RubricItem` 字段校验（id 非空、max_score 有限正数）；`validate_rubric()` **先截断再归一**，末尾断言合计为 100（容差 0.05）；不合法时把错误回喂模型重试，仍不合法则抛出；界面"校验并应用"走同一套校验。
- 测试：`tests/test_models.py` 8 项（13 项输入 → 12 项合计 100）。

### P0-5 隐私泄露与上传持久化

- 问题：`tools/anonymize.py`（受 git 跟踪）里写有**真实姓名、学号与本机目录结构**（此处不转录，避免二次泄露）；上传文件存共享目录且用原始文件名。
- 修改：脚本改为从 `tools/sources.local.json`（已 gitignore）读取清单，支持 `--sources`；新增 `sources.local.example.json` 模板；上传写入受控临时目录 `data/tmp_uploads/` + UUID 文件名，解析结束在 `finally` 中删除；`report_id` 用随机值；限制 20MB；界面明确提示报告会发送到模型服务。
- 测试：`tests/test_security.py` 6 项，含"受跟踪文件不得出现真实身份信息"的 `git grep` 断言。

### P1 关键项

- **P1-1 分数契约**：新增 verdict↔score 合法区间（`SCORE_BANDS`），矛盾时**只标记转人工、不静默改分**；界面导出同时显示 AI 分与最终分。
- **P1-2 Rubric 过期**：`Rubric.source_hash`，教师改了标准原文/课程背景即提示失效并阻止沿用；重新生成或编辑后旧结果作废。
- **P1-3 解析器**：合并章节后按真实位置重算偏移（`recompute_offsets`）；新增 `inspect_text()` 解析体检（空/疑似扫描件/超长召回模式都会明确告警）；DOCX 按 XML 顺序读段落与表格（不再把表格追加到文末）。
- **P1-4 提示词注入**：S2/S3 增加安全边界声明，报告内容用 `<report>` 标签包裹；`detect_injection()` 命中后**全部转人工复核且不改动学生原文**。
- **P1-5 成本与容错**：复用 OpenAI 客户端；传输层指数退避（此前只处理 JSON 错误）；调用失败标记 `system_error` 而非普通 miss；`RunInfo` 记录 token/调用数/失败数/JSON 修复次数。
- **P1-6 可审计性**：新增 `RunInfo`（时间、模型、base_url、rubric 原文与哈希、报告哈希、解析覆盖与告警、prompt 版本、调用统计），界面可展开查看。
- **§6 评测体系**：`batch_run` 默认跑完整流水线（`--no-recheck` 可关，且会记录）；输出版本化 `batch_v2_<ts>.json` 且不覆盖旧文件；`benchmark` 新增 `--batch`、Pearson、复核率、系统失败率、耗时/token，输出 `benchmark_v2_<ts>.json`；`import_gold` 修掉"整份空白报告仍报错"的 bug、verdict 改为必填、封存信息（姓名/日期/独立声明）缺失即拒绝生成。
- **§7 交付**：新增 `.env.example`、`requirements-dev.txt`；README 补干净环境从零安装步骤与测试说明；`DEMO_MODE` 改为**代码层真实拦截**（旧实现只是界面提示，模型照样被调用）。
- **稳定性测试**：改为走完整 `run_grading`，统计 verdict 稳定率、分数极差与标准差（旧版只调一次模型、只测一个评分点）。

## 未完成或有意暂缓

| 项目 | 原因 | 风险 | 下一步 |
|---|---|---|---|
| 新版本 benchmark | 沙箱无网络，需真实模型 | 旧数字与新代码不一致会造成误述 | 你联网跑一次，结果自动版本化保存 |
| Git 历史中的真实姓名/学号 | 需要 `git filter-repo`/BFG 重写历史并强推 | **当前公开仓库的历史里仍有泄露** | 决定后再动手；可先轮换相关账号信息 |
| OCR / 多模态 / 向量检索 | 明确不做，已写入能力边界 | 扫描件会判低 | 主页与 README 已声明不支持 |
| 两位评分者独立打分与人际一致性 | 需要第二个人力 | gold 只有单人，公信力有限 | 决赛前补一人；`import_gold` 已支持校验评分者信息 |
| 并发与 prompt caching | 原型阶段收益有限 | 长报告成本高 | 若继续做再评估 |
| 对抗样本的真实模型端到端测试 | 需联网 | 只有 mock 层验证 | 重跑 benchmark 时加一份注入样本 |
