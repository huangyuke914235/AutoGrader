# bugfix #5：学科选项「名不副实」—— 5 个选项，2 张词表

日期：2026-09-24
发现者：用户（在界面上换学科，发现分数一模一样）
影响面：学生自检 Tab 的「实验类型 / 课程背景」下拉框

---

## 一、现象

同一份报告，界面上依次选：

| 选项 | 体检总分（样本 S03） |
|---|---|
| 计算机类实验 | 84.8 |
| 大学物理实验 | 62.4 |
| 通用理工科实验 | 62.4 |
| 基础化学实验 | 62.4 |
| 生物实验 | 62.4 |

**四个选项给出完全相同的分数。** 用户问：这算不算 bug？

**算。** 而且是典型的一类 bug：界面承诺了引擎没有的能力。

---

## 二、定位

写了个临时诊断脚本，遍历所有选项 × 所有样本，打印每组的分数：

```
⚠️ 结果完全相同的选项组：
[['大学物理实验', '通用理工科实验', '基础化学实验', '生物实验']]
```

再追 `pick_profile()`，原因一目了然：

```python
# 修复前
def pick_profile(experiment_type=""):
    t = (experiment_type or "").lower()
    if any(h in t for h in CS_HINTS):
        return "计算机类实验"
    return DEFAULT_PROFILE          # ← 剩下的全落到这里
```

而 `PROFILE_KEYWORDS` 里当时只有 `理工科实验`、`计算机类实验` **两张**表。

界面有 5 个学科选项，词表只有 2 套 → 物理 / 通用理工科 / 化学 / 生物 四个选项
全部走 `DEFAULT_PROFILE`，用的是同一套关键词、同一套判据 → 分数当然一模一样。

**根本原因不是"写错了一行"，是接口与实现没有对齐：**
下拉框是在 UI 层手写的字符串数组，词表是在引擎层的 dict，
两边没有任何东西保证它们一一对应。加选项不需要动引擎，于是选项一路加，词表没跟上。

---

## 三、修复

### 1. 补上缺失的 3 张词表

`PROFILE_KEYWORDS` 从 2 张扩到 5 张（新增 `大学物理实验` / `基础化学实验` / `生物实验`），
每张表按该学科**真实的小标题习惯**写，不是换皮：

| 学科 | 只有自己认得的章节名 | 说明 |
|---|---|---|
| 基础化学实验 | 试剂与仪器 / 仪器与试剂 / 实验用品 / 实验装置 | 化学报告用「试剂与仪器」代替「实验步骤」，它决定实验能否复现，归到步骤槽 |
| 基础化学实验 | 实验现象 / 称量数据 / 滴定数据 / 产率计算 / 偏差分析 | 化学关心现象记录和产率，不是误差不确定度 |
| 生物实验 | 材料与方法 | 生物报告的规范化章节名，等价于理工科的「实验步骤」 |
| 生物实验 | 观察记录 / 实验结果 / 统计分析 | 生物用「观察记录」而不是「数据记录」 |
| 大学物理实验 | 测量方法 / 不确定度计算 / 系统误差 / 随机误差 | 物理把不确定度单独成章 |

### 2. 加学科派发表

```python
# 学科 -> 触发词。先于 CS_HINTS 匹配，避免「生物信息学」被「信息/程序」抢走
DISCIPLINE_HINTS = {
    "基础化学实验": ("化学", "无机", "有机", "分析化学", "物化", "化工", "滴定"),
    "生物实验": ("生物", "遗传", "细胞", "微生物", "分子生物", "生理", "生态", "解剖"),
    "大学物理实验": ("物理", "力学", "光学", "电磁", "热学", "声学", "近代物理"),
}

def pick_profile(experiment_type=""):
    t = (experiment_type or "").lower()
    for profile, hints in DISCIPLINE_HINTS.items():
        if any(h in t for h in hints):
            return profile
    if any(h in t for h in CS_HINTS):
        return "计算机类实验"
    return DEFAULT_PROFILE
```

顺序有讲究：`DISCIPLINE_HINTS` 必须**先于** `CS_HINTS`，
否则「生物信息学」会被 `CS_HINTS` 里的「信息」抢到计算机词表。

### 3. 选项列表收归单一真源（治本）

这是最关键的一步。原来选项写在 `app.py` 里，是另一份字符串数组：

```python
# 修复前 app.py
["计算机类实验（Java / Python / 编程）", "大学物理实验", "通用理工科实验",
 "基础化学实验", "生物实验", "自定义…"]
```

现在移到 `selfcheck.py`，界面只引用：

```python
# selfcheck.py —— 唯一真源
UI_OPTIONS = [
    "计算机类实验（Java / Python / 编程）", "大学物理实验", "基础化学实验",
    "生物实验", "通用理工科实验", "自定义…",
]

# app.py
st.selectbox("实验类型 / 课程背景", SC.UI_OPTIONS, key="sc_exp_sel")
```

再由测试锁死双向一一对应（见下）。**以后加学科，只改一处；少配词表，测试立刻红。**

## 四、修复前后

同一份生物报告（用「材料与方法 / 实验结果 / 讨论」这类生物专属标题）：

| 词表 | 结构项得分 | 识别章节 | 总分 |
|---|---|---|---|
| 生物实验（正确） | 100.0 | 8/8 | **55.2** |
| 理工科实验 | 62.0 | 5/8 | 48.6 |
| 基础化学实验 | 50.0 | 4/8 | 46.6 |
| 计算机类实验 | 62.0 | 5/8 | 42.6 |

同一份报告换学科，分数真的会动了。

---

## 五、必须说清楚的一个诚实例外

修复后，用**通用小标题**写成的报告（实验目的 / 实验原理 / 实验步骤 /
数据记录 / 数据处理 / 误差分析 / 结论 / 参考文献），在物理 / 化学 / 生物 /
通用理工科下**仍然会得到相同的分数**。

**这不是 bug。** 这类标题是各学科词表的公共交集，谁都能全部命中。
学科词表的价值只体现在**不按通用标题写**的报告上——正是上面那份生物报告的情形。

这条已经写进体检工具的输出里，避免以后有人又当成 bug 报一次：

```
注：以下学科得分相同（该报告用的是通用小标题，属正常）：[['理工科实验', '大学物理实验']]
```

## 六、回归测试

`tests/test_selfcheck.py` 新增 3 条：

1. `test_each_ui_option_maps_to_its_own_profile`
   每个选项必须落到不同的词表；且不允许有"没有任何选项能选中"的词表（防死代码）。
2. `test_discipline_specific_headings_recognized_only_by_matching_profile`
   「试剂与仪器」只有化学词表认得，「材料与方法」只有生物词表认得，别的词表都不许认。
3. `test_biology_report_scores_higher_under_biology_profile`
   生物报告在生物词表下的总分必须高于通用理工科。

外加常驻体检工具 `tools/check_profiles.py`（原临时脚本 `_diag_profile.py` 转正）：

```
python tools/check_profiles.py
```

它回答三个问题：选项↔词表是否 1:1、换学科分数是否真的变、专属标题有没有被别的词表抢走。
任何一条不成立就退出码 1。

---

## 七、遗留

- 目前 5 张词表（理工科 / 计算机 / 物理 / 化学 / 生物）。医学、电子、材料等尚未覆盖，
  需要时按同样的两步加：写词表 + 加 `UI_OPTIONS` 条目，测试会自动校验。
- 词表只影响**章节识别**（结构完整性这一项）。数据行、图表编号、引用格式等判据
  目前仍是跨学科统一的，学科差异没有渗透进去。这是下一步可选的深度。
