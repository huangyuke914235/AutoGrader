# 可打印成绩单导出（PDF）

## 它是什么

评阅结果多一个出口：**一份能直接打印、能转发、能截图的成绩单**。
位置在「④ 导出」页，紧挨着 CSV / JSON。

用 `report_pdf.build_grading_pdf(res, course=...)` 生成，返回 PDF 字节。
零新增依赖 —— `requirements.txt` 里已经有 pymupdf（本来用来解析 PDF），
它内置的 CJK 字体能直接写中文，不必为一张成绩单再拖进 weasyprint / reportlab 那一整条链。
「读 PDF」与「写 PDF」必须落在同一个库对象上，所以统一走 `parser.import_fitz()`。

## 硬约束：这份单子不能长得像一份正式成绩

它会离开这个页面（打印、转发、截图），脱离上下文的某一页同样不能被误读。所以：

- 第一页**顶部**（标题正下方）就写「本单由 AI 依据既定评分标准生成，仅供参考；
  教师可逐项调整，最终成绩以教师评定为准」——不是藏在末尾的小字；
- **每一页的页脚**都重复一遍「AI 评阅建议稿 · 仅供参考 · 最终成绩由教师评定」，
  并标注页码；
- 末尾单列「本单的边界」四条：分项分由代码加总分、证据是逐字引用并经 Python 精确匹配、
  系统错误不计入分母也绝不当 0 分、本单不构成成绩认定。

对应测试：`test_disclaimer_is_on_the_paper`、`test_long_report_does_not_crash_and_paginates`
（后者断言页脚免责声明出现次数 ≥ 页数 − 1）。

## 字体：优先内嵌系统字体，内置字体兜底

`pymupdf` 内置的 CJK 字体（`china-s`，Droid Sans Fallback）有一个很别扭的性质：
**它把西文也当全角排**。实测数据：

| 字体 | `deepseek-chat`（12 字符，字号 9.5pt）每字符宽度 |
|---|---|
| `china-s` | 9.50 pt（= 1.00 em，正好一个字宽） |
| 内嵌 `msyh.ttc` | 5.13 pt（≈ 0.54 em，正常半角） |

也就是说，用内置字体时模型名会被印成「d e e p s e e k - c h a t」。
这张单子是要交到老师手上的，不能这样出厂。

策略：`_pick_font()` 依次探查 Windows / macOS / Linux 常见中文字体路径，
找到就 `insert_font` 内嵌；**找不到就退回内置字体**。

- 退回是必须保留的兜底，不是备选：云端容器不一定装了中文字体，
  只认系统字体的话部署过去就是满纸方框或空白，而且**不会报错**。
- 内嵌失败（字体文件损坏等）时会全局退回内置，并清空 `font_path`，
  使退回只发生一次 —— 避免出现「前几页一个字体、后几页另一个字体」。
  实测损坏的字体文件会在 `insert_font` **当场**抛 `FzErrorLibrary`，
  所以这个 `try` 是能可靠接住的，不会拖到写文字时才爆。

对应测试：`test_latin_is_not_typeset_full_width`（无系统字体时显式 skip，
不假装通过）、`test_broken_system_font_falls_back_to_builtin`。

### 体积：必须做字体子集化

内嵌的是**完整的**系统字体文件（`msyh.ttc` ≈ 19MB）。不裁剪的话，
一份三四页的成绩单实测 **18.76 MB** —— 这个体积放进下载按钮是荒唐的。

`_Doc.tobytes()` 里调 `doc.subset_fonts()` 只保留页面真正用到的字形，
并显式开 `deflate`（`tobytes` 默认不压缩，`save` 的默认值才是压缩）：

| | 单页示意 | 真实四页成绩单 |
|---|---|---|
| 不子集化 | 18.76 MB | 19.6 MB |
| 子集化后 | 0.09 MB | 0.25 MB |

中文与西文提取、渲染都正常。对应测试：`test_score_sheet_stays_small_enough_to_send`
（门槛 2MB，故意设很松，只在有人删掉 `subset_fonts()` 时变红）。

## 系统错误项：绝不能印成「0 分 · 未达」

这是本次最要紧的一处修正，也是踩过的坑。

`pipeline.system_error_judgement()` 给系统错误项填的是 `verdict="miss"`、`score=0`
（见 `pipeline.py` 的注释：「系统错误 ≠ 学生没做到」）。
照原样印出来，纸上就是：

> 【5】格式规范　满分 15 ｜ AI 判定 **0（未达）** ｜ ……
> 系统错误：模型返回的 JSON 中 score 字段缺失……该项不计入总分，需人工判定。

上面一行说「0 分，未达」，下面一行说「不计入总分」—— **自相矛盾**，
而读者只会记住上面那行。这份单子还要被打印、被截图的，光靠底下一行红字救不回来。

改法：`_judgement_text()` 一旦发现 `system_error`，就**完全不显示** AI 判定与分数，改为：

> 【5】格式规范　满分 15 ｜ **系统错误，本次未作出判定** ｜ 最终 **待人工判定**

对应测试：`test_system_error_item_never_shows_a_score`。
这条测试自带**反向对照** —— 把 `system_error` 标记摘掉，同一份数据立刻会被印成
「0（未达）」，证明断言不是空的。

## 顺带加固的一处

`app.py` 的「② 详情」页原来用硬下标读 `st.session_state["full_text"]`。
结果与原文眼下总是成对写入，所以触发不到；但一旦缺了
（比如将来给评阅结果也做「回看历史」，只还原结果、没还原原文），
**整个详情页会打崩**，而实际只是少显示一块内容。已改为 `.get(...) or ""` 并给出降级说明。

```bash
python -m pytest tests/test_report_pdf.py -q

# 生成样例，人工核对排版
python tools/make_pdf_sample.py     # → docs/样例-可打印成绩单.pdf
```

样例刻意覆盖全部状态（命中 / 部分命中 / 未达 / 系统错误未判定 / 人工改分 /
证据被作废），数据是合成的，不含真实学生报告。系统错误项直接用生产代码的
`system_error_judgement()` 构造，避免样例写出「现实里不会出现的组合」而变成自欺。

## 已知边界

- 成绩单只覆盖「一次评阅」。跨次的进步趋势在「⑥ 学生自检 → 版本对比」里，
  两者的分数口径不同（自检是通用规范、评阅是教师 rubric），**不要横向比较**。
- PDF 里的分数与界面一致，均按百分制；`total` 由代码加总，不接受模型输出。
- 导出失败只影响这一个附件：CSV / JSON 仍可下载，界面会说明失败原因。
