(1.1) JDK下载安装与环境配置
操作步骤
下载最新LTS版本JDK
访问Oracle官方网站，下载最新长期支持（LTS）版本Java SE Development Kit 25（Windows x64 Installer版本）。Java 25是Oracle官方2025年发布的LTS版本，提供长期安全更新与技术支持。
安装JDK
运行下载的安装程序，选择默认安装路径（如C:\Program Files\Java\jdk-25），安装过程中会同时安装JRE（Java运行环境）。安装完成后，JDK目录下包含bin（可执行命令）、lib（类库）、jmods（模块文件）等子目录。
配置系统环境变量
右键“此电脑”→“属性”→“高级系统设置”→“环境变量”。
新建系统变量JAVA_HOME，值为JDK安装路径C:\Program Files\Java\jdk-25。
编辑系统变量Path，添加%JAVA_HOME%\bin，确保Java命令可在任意目录下调用。
（可选）新建CLASSPATH变量，值为.;%JAVA_HOME%\lib，表示当前目录为类加载路径。
验证安装成功
按下Win+R输入cmd打开命令提示符，依次执行以下命令：
java -version：查看Java运行时版本，输出JDK 25相关信息则安装成功。
javac -version：查看Java编译器版本，与JDK版本一致则配置正确。
java -verbose：查看类加载路径，验证环境变量生效。

(1.3) Java SE 26 安全编码指南解读
Oracle官方发布的《Secure Coding Guidelines for Java SE》是Java开发者构建安全可靠应用的核心规范，涵盖从基础设计到具体编码的全流程安全要求，核心内容可分为以下几个层面：
第一，安全编码基础原则。指南提出“代码应具备显而易见的安全性，而非看似无缺陷”的核心理念，强调安全是设计出来的而非后期修补的。开发者需要先识别应用的信任边界与数据类型，通过威胁建模明确安全风险点，再针对性选择编码规范。指南特别指出，安全编码不聚焦于加密算法等专业安全功能实现，而是覆盖通用代码的健壮性与权限控制，避免因基础编码漏洞引入安全风险。
第二，输入验证与数据安全。所有来自不可信源的输入都必须进行严格校验，优先使用白名单机制验证数据类型、长度、范围与格式，而非黑名单过滤。对于序列化场景，敏感字段必须声明为transient避免被序列化，防止攻击者通过字节流分析获取私有数据；同时禁止在序列化过程中调用可重写方法，避免多态行为引发安全漏洞。对于日志与异常信息，严禁输出密码、身份证号等敏感信息，防止信息泄露。
第三，访问……

……从“纯Java后端”转向“Java+AI集成”。传统Java开发只需掌握Spring全家桶、数据库、微服务即可，而当前需要具备大模型应用落地能力，理解RAG、Agent编排、向量数据库等技术，能够将大模型API无缝集成到现有Java系统中，通过Spring AI等框架实现智能问答、自然语言查询等业务功能，完成从“提供接口”到“提供智能服务”的转变。

Part 3 面向对象类设计（30分）
(3.1) 银行账户类 BankAccount
类设计说明
BankAccount类封装银行账户的核心属性与操作，通过构造方法初始化账户信息，deposit与withdraw方法实现资金变动，withdraw方法保证余额不为负，toString方法统一输出账户信息。分别通过类内部main方法与外部测试类main方……

……ter/setter方法，可保证数据的合法性与一致性，避免外部随意修改内部状态。封装降低了模块间的耦合度，内部实现的修改不会影响外部调用，大幅提升代码的可维护性。
继承是实现代码复用与层次化设计的核心机制，允许子类继承父类的属性与方法，并扩展自身特性。设计时应遵循“里氏替换原则”，子类可以替换父类出现的任何位置而不破坏逻辑。合理的继承结构能够抽取公共逻辑到父类，减少重复代码，同时形成清晰的类层次关系，便于系统扩展。但继承会增强类间耦合，应避免过深的继承层级。
多态是面向对象的灵活性来源，指同一操作作用于不同对象可以产生不同的执行结果，主要通过方法重写与接口实现。多态让程序可以面向抽象编程，而非面向具体实现，提高了代码的可扩展性与复用性。新增功能时只需添加新的实现类，无需修改原有调用逻辑，符合“开闭原则”。
总体而言，三大特性共同支撑了面向对象的核心优势：封装保障安全性与低耦合，继承实现代码复用，多态提升系统灵活性。遵循这些原则设计的类结构清晰、易于扩展、便于维护，能够有效降低大型软件的开发与迭代成本。（全文约490字）
