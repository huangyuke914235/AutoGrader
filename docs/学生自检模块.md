# 学生自检模块（Self-Check）

## 它是什么

在教师向的评阅流水线之外，**新增一条学生向的链路**：学生自己上传报告做质量体检，
拿到「问题 + 位置 + 改进方向」，改完再传一次看进步。

两条链路的关系是**并列而非替代**：

| | 评阅（pipeline.py） | 自检（selfcheck.py） |
|---|---|---|
| 使用者 | 教师 / 助教 | 学生 |
| 评价性质 | 总结性评价（要出成绩） | 形成性反馈（帮学生改） |
| 依据 | 教师写的 rubric | 通用实验报告规范（12 项） |
| 输出 | 分项分数 + 原文证据 + 待复核标记 | 问题定位 + 改进方向（无成绩含义） |
| 人在回路 | 教师复核定分 | 学生自己改、自己复检 |

## 12 个检查项

| 检查项 | 权重 | 引擎 | 判什么 |
|---|---|---|---|
| 结构与完整性 | 10 | 规则 | 8 个标准语义槽是否齐全 |
| 实验目的 | 6 | 规则 | 目的是否写清「要做什么、用什么方法」 |
| 步骤可复现性 | 10 | 规则 | 是否编号、是否带具体参数（理工科看量程单位，计算机类看版本/路径/命令） |
| 原始数据表 | 10 | 规则 | 理工科：表格标识 + 原始读数行；计算机类：运行结果/输出是否有实质内容 |
| 有效数字 | 6 | 规则 | 数据行小数位是否统一（只统计一行 ≥2 个数字的行） |
| 单位与量纲 | 4 | 规则 | 理工科：数值是否带单位；计算机类：结果是否量化（准确率/损失/耗时） |
| 图表规范 | 6 | 规则 | 图/表是否有**编号**与标题 |
| 引用与格式 | 6 | 规则 | 编号引用 `[1]`，或链接 / `《文档名》` 形式的出处 |
| 原理阐述 | 8 | AI | 原理推导是否完整、是否支撑实验设计 |
| 数据处理与计算 | 12 | AI | 计算过程、不确定度是否到位 |
| 误差分析 | 12 | AI | 是否区分系统/随机误差并给出量级 |
| 结论与讨论 | 10 | AI | 结论是否被数据支撑、有无偏差讨论 |

**为什么不全交给模型**：前 8 项是确定性规则，正则判既免费又稳定可复现。
学生「改完再测」时，规则项的分数变化是可信的，不会被模型抖动污染；
模型只做真正需要语义的 4 项，单次成本约降一半。

### 学科自适应（为什么必须有）

一份 Java 实验报告里没有「实验原理」「误差分析」这类小标题，取而代之的是
「技术要点」「错误分析」「运行结果」。用理工科词表去套，同一份 S02 只能认出 1/8
个章节 —— 这是**系统性假阴性**，不是学生写得差。

`PROFILE_KEYWORDS` 目前五套词表，与界面下拉框选项一一对应：

| 界面选项 | 词表 | 只有它认得的章节名 |
|---|---|---|
| 计算机类实验（Java / Python / 编程） | 计算机类实验 | 误差分析 ← 错误分析、局限、边界；原始数据表 ← 运行结果、输出、生成结果 |
| 大学物理实验 | 大学物理实验 | 测量方法；数据处理 ← 不确定度计算；误差分析 ← 系统误差、随机误差 |
| 基础化学实验 | 基础化学实验 | 试剂与仪器、仪器与试剂、实验装置；实验现象、滴定数据、产率计算、偏差分析 |
| 生物实验 | 生物实验 | 材料与方法（≈ 理工科的「实验步骤」）；观察记录、统计分析 |
| 通用理工科实验 | 理工科实验（默认） | 误差分析 ← 误差分析、不确定度；原始数据表 ← 数据记录、原始数据 |

选项字符串定义在 `selfcheck.UI_OPTIONS`，界面直接引用，**不在 UI 里另写一份**。
原因见 `docs/bugfix-学科选项名不副实.md`：曾经界面有 5 个学科、引擎只有 2 套词表，
四个选项跑出完全相同的分数。现在：

- 派发顺序 `DISCIPLINE_HINTS` → `CS_HINTS` → 默认（`DISCIPLINE_HINTS` 必须靠前，
  否则「生物信息学」会被「信息」抢到计算机词表）；
- `test_each_ui_option_maps_to_its_own_profile` 双向锁死：每个选项落不同的词表，
  且不允许存在选不中的词表；
- 常驻体检工具 `python tools/check_profiles.py`。

界面上会把实际选用的词表写出来，学生发现不匹配可以改选实验类型。

**诚实例外**：用通用小标题写的报告（实验目的 / 实验原理 / 实验步骤 / 数据记录 /
数据处理 / 误差分析 / 结论 / 参考文献），在各学科下仍会得到相同分数 ——
它们是所有词表的公共交集，谁都能全中。学科词表的价值只体现在**不按通用标题写**
的报告上（如生物报告的「材料与方法」）。这不是 bug，体检工具会显式标注。

## 三条硬约束（已落成代码，不是文档里的口号）

1. **总分由代码加总** —— `SelfCheckPayload` 里没有 total 字段，权重也不归模型管
   （与 `models.GradingResult` 同一条纪律）。
2. **只诊断不代写** —— 改进方向在代码层强制截断到 40 字（`MAX_DIRECTION_LEN`），
   prompt 层明令禁止给出可抄录正文、禁止生成数据/图表/参考文献。
3. **系统错误 ≠ 学生没做到** —— AI 不可用（未配密钥 / DEMO_MODE / 调用失败）时，
   对应项置「未检测」并**从总分分母中剔除**，绝不当成 0 分算给学生
   （纪律同 `pipeline.system_error_judgement`）。

## 复用了什么（没有另起一套）

- 文档解析：`parser.parse_file` / `split_sections`（与评阅同一份规范文本）
  - ⚠️ 自检额外要 `keep_lines=True` 的第三份返回值（保留换行的原文）。
    `canonical()` 会把换行压成空格，行级规则（章节定位 / 编号步骤 / 数据行）必须拿原文才准，
    详见 `docs/bugfix-自检规则引擎假阴性.md`
- 模型调用：`llm.call_json`（四级宽容解析、重试退避、DEMO_MODE 拦截、用量统计）
- 上下文构建：`parser.build_context`（超长文档自动召回）
- 防注入：随机数据边界标签 `<report-xxxxxxxx>`（与 `pipeline.stage_judge` 同一套做法）
- 界面：复用 `load_sample` / `load_uploaded` / 20MB 上限 / 脱敏提示

## 怎么用

界面：第 ⑥ 个标签页「学生自检」。

命令行（供脚本与测试使用）：

```python
import parser as P, selfcheck as SC
full_text, sections, raw_text = P.parse_file("xxx.pdf", keep_lines=True)
res = SC.run_selfcheck(full_text, sections, experiment_type="大学物理",
                       use_ai=True, raw_text=raw_text)
print(res.total, res.undetected)
print(SC.to_markdown(res))
```

## 已知边界

- 扫描件 PDF 无法解析，规则项会全部判缺失并提示先做 OCR（属解析失败，不算学生问题）
- 章节关键词偏中文实验报告；英文报告需扩展 `PROFILE_KEYWORDS`
- 只有两套词表（理工科 / 计算机类）。化学、生物、医学等暂按理工科词表跑，
  界面已写明实际用的是哪套，但判据不一定贴合，需要时加一套即可
- 「运行结果」是否算「有内容」目前靠长度与数字密度估算，
  真实输出贴的是截图时识别不到（截图里的文字不进正文）
- 自检历史存在 `st.session_state`，刷新即失效；要持久化需接数据库
- 体检分不具备成绩含义，界面与导出物上都必须保留免责说明
