# 3 分钟演示视频分镜脚本（含口播逐字稿）

> 用法：左边是时间轴，中间是**画面上要发生的操作**，右边是**照着念的口播**。
> 彩排 2 遍再录；录屏建议 1920×1080、浏览器全屏、关掉所有通知与弹窗。
>
> **三条录制要求**：
> 1. 必须跑**真实模型、真实报告**，不允许预置假结果、不允许剪接成"秒出分"的假象；
>    等待过程可以加速，但要在字幕上写"此处已加速 N 倍"。
> 2. 演示用的报告必须是**已脱敏**的版本，学号/姓名不能出现在画面里。
> 3. 视频里说的每一个数字，都必须和仓库里的 `tools/benchmark.py` 输出一致；
>    若录制前重跑过 benchmark，**以新的数字为准**。

## 分镜表

| 时间 | 画面 / 操作 | 口播逐字稿 | 字幕 / 标注 |
|---|---|---|---|
| **0:00–0:12** | 黑底白字打出两行：助教批改 60 份实验报告 ≈ 10 小时；同一份报告连跑 10 次，2 次判定会漂 | 「一个助教批改 60 份实验报告，要花掉差不多 10 个小时；更麻烦的是，同一份报告、同一套标准，过一会儿再改，分数可能就不一样了。」 | 字幕：10 小时 / 2 次漂移（数据由 `tools/stability_test.py` 连测得到） |
| **0:12–0:22** | 切到 PPT 第 2 页（痛点），停 3 秒 | 「所以我们没有做"让 AI 打个分"，因为那只是把黑箱换了个更大的黑箱。我们做的是——把老师的评分标准，变成一条**可核查、可溯源、可校准**的判定流水线。」 | 「AutoGrader · 实验报告智能评阅平台」 |
| **0:22–0:45** | 打开在线 Demo。①「内置脱敏样本」选 `S02`，显示字数与章节数；②展开「原始版面对照」停 2 秒再收起；③在右侧输入自然语言评分标准 | 「先看真实操作。左边是一份已经脱敏的实验报告，右边是老师用大白话写的评分标准——就一句话，比如'有实验目的、步骤完整、有运行结果、有分析总结，总分 100'。展开这里是原始版面，老师可以随时对照报告里的表格和截图。」 | 高亮：报告字数 / 章节数；字幕：原始版面对照（PDF 渲染，仅供人看） |
| **0:45–1:05** | 点「① 生成评分点」→ 出现 N 个原子评分点 → 切到「③ 评分点」页，改一个分值，把合计展示为 100 | 「第一步是把它拆成可以单独判定的原子评分点。注意这里有个**人在回路**的关口：老师可以改分值、可以增删，改完立刻生效。系统不会替老师把标准定死。」 | 标注「人在回路 · 关口一」 |
| **1:05–1:30** | 回到「① 评阅」→ 展开「多模态 OCR」→ 勾选后点「② 开始评阅」→ 进度条先走 OCR 再逐点推进（此处可加速，标注倍数） | 「这一步解决我们最大的一个缺口。实验报告最关键的证据往往是**截图**——运行结果、报错、结果表格。以前正文里只抽得到"运行结果示例"这行标题，截图里的内容读不到，这一整类报告就被系统性判低。现在我们逐页渲染成图片交给多模态模型转录，**每页都带页码**，于是截图里的数据也进了证据链，引用可以精确指到第几页。读不出来就写无法辨认，绝不编造。」 | 字幕：多模态 OCR（deepseek-flash，逐页读图，可缓存不重复计费） |
| **1:30–1:58** | 出分后切到「② 详情对照」：左侧原文高亮，右侧逐点卡片展示判定/置信度/理由/证据；点「定位」跳转 | 「出分之后是最关键的一页：左边是报告原文，命中的证据已经高亮；右边是每个评分点的判定、置信度和理由。任何一个分数，都能追到原文里那一行字。**引用是不是真的在原文里，不是模型说了算，是代码逐字校验的**——校验不通过就作废重跑，两次都不过就清空证据转人工。」 | 圈出「置信度」「待复核」标记；字幕：证据经代码逐字校验 |
| **1:58–2:15** | 在「人工覆盖」里改掉一个分数并填理由 → 展示导出（CSV / 打印成绩单） | 「如果老师不认同，可以直接改分并留下理由——**最终拍板的永远是人**，AI 只负责给出带依据的初判。这一页可以导出成绩表和可打印的成绩单。」 | 标注「人在回路 · 关口二：可覆盖、留痕」 |
| **2:15–2:50** | 切到「⑤ 批量测试与班级学情」：先展示多份对比表，再往下滚到**班级学情看板**（分数分布、共性短板条形图、建议动作、需要关注的学生） | 「这一页是这次重新打磨补上的重点。赛题方向是'AI + 教学**管理**助手'，而管理要回答的不是'这份报告几分'，是三个问题：**这个班普遍卡在哪、下一节课该讲什么、谁需要我找一趟**。看板把一批报告聚合成共性短板——这里是 12 份的演示队列，系统自己算出'分析与总结'这一项 7 份没拿满，是这次最该占用课堂时间的地方；建议也不写'加强练习'这种废话，而是告诉你整项缺失通常是要求没落到纸面，建议在作业说明里写成可勾选的要求。**分数来自模型、共性短板来自算术**，这个区分在界面上是分开写的。」 | 数字放大出现：「12 份 · 均分 73 · 及格率 66.7% · 最短板 7/12」 |
| **2:50–3:05** | 切到 PPT 自评测页：四次评测数字并列 | 「我们也给自己安排了一次闭卷考试：9 份报告由不参与开发的队友独立人工打分并封存，直到评测当天才拆。修复前后四轮完整评测的数字我们都列出来了，**修复前那一轮 20.44 分作为对外主指标**——因为修复发生在基准集解封之后，严格来说不算盲测，我们无法自证没沾到它的光。」 | 「31.67 → 20.44 → 7.56 → 6.67~6.89」，标注「修复前数值为对外主指标」 |
| **3:05–3:15** | 切到 PPT 第 3 页：RAG-E 四阶链 + 三条工程约束 | 「整条链路叫 RAG-E：评分点原子化、证据锚定判定、一致性守卫、反馈生成。三条工程约束是——分数由代码加总、无证据的判定不算数、不确定就交给人。」 | 「R → A → G → E」逐段点亮 |
| **3:15–3:25** | 团队页 / 仓库二维码 | 「我们是深圳大学的两名本科生。代码、排查记录和这份自评测，全部开源在仓库里，欢迎复现。」 | 仓库地址 + 二维码 |

> ⏱ **总时长 3:25，按赛方 3 分钟上限需要裁**。裁减优先级（从先删起）：
> ① 0:12–0:22 的 PPT 痛点页压到 5 秒；
> ② 1:05–1:30 的 OCR 段压到 15 秒（只保留"截图里的数据也能进证据链、可指到第几页"）；
> ③ 1:58–2:15 的改分与导出压到 10 秒。
> **优先保证 2:15–2:50 的班级学情段完整** —— 它是「教学管理」这个方向的直接交代，
> 也是这一版相比初赛版本最大的增量。

## 这句话不要再说了（初赛版本的过期说法）

| 过期说法 | 现在的实际情况 |
|---|---|
| 「这些图片内容系统读不到，也不会成为评分依据」 | **已支持多模态 OCR 读图**。只有**没开启** OCR 时才是读不到的；开启后截图内容会转录成带页码的可引用正文。OCR 是可选开关，不是能力缺失。 |
| 「不支持图片与截图（无 OCR）」 | 同上，已不成立。README 与主页均已改写。 |
| 「⑤ 批量测试」 | 现在是「⑤ 批量测试与班级学情」，多了教学管理那一半。 |
| 只讲 MAE 一个数字 | 对外主指标仍是修复前的 20.44，但要把四轮完整评测一并列出（PPT 自评测页已如此）。 |

## 录制注意事项

| 情况 | 处理 |
|---|---|
| 录到一半模型超时/限流 | 录制前先跑一次预热；若失败，等待后重跑该段，不要剪接成"一次成功" |
| 报告里出现真实姓名学号 | 只用 `data/samples/` 里已脱敏的样本，录前全文扫一眼 |
| 说错数字 | 数字单独录一条备用素材，方便替换 |
| 页面加载慢显得"卡" | 允许加速，但字幕必须写明"已加速"，不许假装实时 |
