# 缺陷复盘 #4：自检规则引擎把完整报告判成 17 分（系统性假阴性）

> 与前三轮不同，这次**不是**评阅流水线的问题，而是新加的学生自检模块。
> 记下来是因为它踩的坑有普遍性：**复用别人的基础设施时，
> 必须先搞清楚那份数据被做过什么加工。**

---

## 1. 现象

把学生自检接到队友的源码上之后，用内置样本 S02（一份 3507 字的 Java 实验报告，
结构完整、有环境配置步骤、有代码与分析）跑一次体检，规则部分总分 **17.2 / 100**。

逐项看更离谱：

| 检查项 | 判定 | 系统给的理由 |
|---|---|---|
| 结构与完整性 | 12 分 | 识别到 1/8 个标准章节 |
| 步骤可复现性 | 20 分 | 识别到 **0** 个编号步骤 —— 可报告里明明有 `(1.1)` `(1.2)` `(2.1)` |
| 原始数据表 | 0 分 | 发现 0 行疑似数据 |
| 图表规范 | 100 分 | 发现 2 个图表 —— 实际一处图都没有 |

四个问题里三个假阴性、一个假阳性，方向还不一致，像是随机出错。

## 2. 排查

### 2.1 第一层：学科词表不对

S02 是计算机类报告，根本没有「实验原理」「误差分析」这类小标题，
取而代之的是「技术要点」「错误分析」「运行结果」。
而自检最初只有一套理工科词表（`SECTION_KEYWORDS`），章节槽位匹配不上，
于是「结构与完整性」被判 1/8。

先修词表：拆成 `PROFILE_KEYWORDS`，按实验类型选「理工科实验 / 计算机类实验」。
分数从 17.2 涨到 34.8——**说明词表是一个原因，但不是全部**。

### 2.2 第二层（真正的根因）：正文被压成了一行

继续查为什么「0 个编号步骤」。直接在原文上跑同一个正则：

```
STEP_PATTERN 在原文上匹配：8 个
STEP_PATTERN 在传入的文本上匹配：0 个
```

同一个正则、同一份报告，结果差 8 倍。差异只可能来自文本本身。
翻 `parser.parse_file`：

```python
def canonical(text):
    return re.sub(r"\s+", " ", text).strip()   # 换行也被压成了空格
```

`canonical()` 是为了修 #3（PDF 断行导致引用匹配不上）而做的，
把**所有连续空白**（含 `\n`）压成一个空格。对引用逐字匹配是必需的，
但代价是：正文从此只有一行。

而自检的行级规则全都建立在「行」之上：

- 按行扫描小标题做章节兜底定位 → 只有一行，永远扫不到 → **1/8 章节**
- `^` 锚定的编号步骤 → 只有行首能匹配一次 → **0 个步骤**
- `\d+\s+\d+` 的数据行 → 单行内也能匹配，但语义已经不是"行"了 → **0 行数据**
- 图表标题是否缺失（看编号后面那一行的剩余内容）→ 判断完全失真

**结论**：不是规则写得差，是喂给规则的文本被加工过，加工方式恰好废掉了全部行级规则。

### 2.3 顺带发现的两个假阳性

修完上面两点后，还剩两个反向错误：

- **图表规范给了 100 分**：`FIGURE_PATTERN` 原本是 `(图|表|截图|Figure|Table)\s*(\d*)`，
  数字是可选的，于是「截���说明」（题目**要求**学生贴图）被当成"已有 2 张图"。
  改成**必须带编号** `(图|表|截图|Fig|Table)\s*(\d+)` 后归零。
- **运行结果明明是空的却给了 70 分**：章节兜底定位从标题往下取 40 行，
  遇到下一个小标题不停，于是空标题「运行结果示例」把后面整节正文都算成自己的内容。
  加上停靠条件后，正确报出「有标题但正文为空」。

## 3. 修复

| # | 改动 | 位置 |
|---|---|---|
| 1 | `parse_file(path, keep_lines=False)`：多返回一份保留换行的原文（向后兼容，不传就是原行为） | `parser.py` |
| 2 | 行级规则只吃 `raw_text`；AI 仍吃 canonical 正文（引用匹配要求不变） | `selfcheck.rule_check(raw_text=…)` |
| 3 | 两套学科词表 + `pick_profile()`，界面写明实际用的是哪套 | `selfcheck.PROFILE_KEYWORDS` |
| 4 | 图表引用必须带编号 | `FIGURE_PATTERN` |
| 5 | 章节兜底定位遇到下一个小标题即停；`sec.text` 剥掉自身标题行 | `_slice_body` / `locate_sections` |
| 6 | 计算机类把「单位与量纲」改判为「结果是否量化」（准确率 / 损失 / 耗时），
      不再拿物理量单位表去数 | `CS_QUANT_PATTERN` |
| 7 | 界面与命令行把 `raw_text` 一路传下去 | `app.load_sample` / `load_uploaded` |

## 4. 修复前后（规则部分，样本均为内置脱敏样本）

| 样本 | 修复前 | 修复后 | 说明 |
|---|---|---|---|
| S02（Java 实验） | 17.2 | **53.8** | 确实缺实验目的、结论、参考文献 |
| S03（RNN 文本生成） | 50.2 | **84.8** | 8 个语义槽齐 7 个，只缺参考文献 |
| S04（对话分类） | 52.1 | **84.8** | 同上 |
| S02 故意用理工科词表 | — | 34.0 | 对照组：词表选错仍会低估近 20 分 |

54 / 85 这类数字不是为了"好看"，对应关系是：S03 / S04 结构完整、有图有数据有分析，
只是没写参考文献；S02 缺目的、缺结论、运行结果为空。

## 5. 为什么值得单独写一篇

1. **复用 ≠ 照抄契约**：`canonical()` 在它自己的场景里是正确的，
   换到行级规则场景就成了破坏性加工。新增模块时要把上游数据的加工史问清楚。
2. **假阴性比报错危险得多**：报错会被发现，假阴性不会——
   学生只会看到"我这份报告只有 17 分"，然后不信这个工具。
3. **学科差异是产品问题不是调参问题**：计算机类报告没有「误差分析」这个章节名，
   这不是学生写错，是词表设计者没覆盖。
