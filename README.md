> 评测口径：基准答案（gold set）由**不参与代码与 prompt 开发**的成员独立打分——
> 打分期间不看系统输出、不与主程讨论，完成后封存，直到评测当天才解封。
> 让写 prompt 的人同时定义「正确答案」，等于对着答案改答案。

## 核心方法论：RAG-E 四阶判定链

```
R 评分点原子化   教师用自然语言写评分标准 → 拆成可独立判定的原子评分点
A 证据锚定判定   逐评分点独立判定，必须回引报告原文；引用经代码逐字校验
G 一致性守卫     低置信自动二次复核，不一致 / 分值差距过大 / 调用失败一律转人工
E 反馈生成       基于已定稿的逐项判定生成总评与可执行改进建议
```

## 三条工程约束

1. **分数由代码加总** —— 模型只输出单点评定（hit / partial / miss 与该项分值），
   总分由代码求和；判定与分值明显矛盾时标记转人工，不会静默改分
2. **无证据的判定不算数** —— 每条引用都必须通过代码的原文**逐字匹配**校验，
   匹配不上就作废重跑（不接受模糊匹配或近似匹配）；两次都不通过则清空证据、转人工复核
3. **不确定就交给人** —— 低置信、两次判定不一致、两次分值差距过大、模型调用失败，
   全部显式标记为「待人工复核」，并在界面上单独计数

## 自评测结果（9 份真实实验报告 vs 封存的人工打分）

评测方法：**9 份**真实报告由**不参与开发的成员**独立人工打分并封存，
直到评测当天解封；系统侧走与产品完全相同的流水线。

> 另收集了 1 份篇幅超长的报告（6.8 万字），**不计入下列任何指标**，单独作为超长模式的压力测试：
> 它在"关键词召回"模式下被判 27 分（人工 43 分），其中「核心实现」整项被判 miss；
> 把全文上限提高到 7 万字、改为全文判定后升到 52 分（人工 43）。
> 结论：**看不到就判没有，会造成系统性低估**——因此现在召回模式下的所有 miss 一律强制转人工复核。
> 该份人工分保留在基准集里，但为避免事后更改评测集，主指标仍只统计预先登记的 9 份。

| 评测版本 | MAE | 误差 ≤5 分占比 | 证据可溯源率 |
|---|---|---|---|
| 修复前（保守值，作为对外主指标） | **20.44** | 0% | 84.9% |
| 迭代后 · 第 1 次（含一致性复核） | 6.89 | 44.4% | 97.0% |
| 迭代后 · 第 2 次（同代码重跑） | 6.67 | 33.3% | 96.9% |

后两次是同一份代码相隔一段时间跑的完整评测，**指标落在 6.67 ~ 6.89 的区间内**，
相关系数 0.907 ~ 0.936，系统失败率 0%。对外给出区间而非单次最优值 ——
这个量级的波动，正是「AI 只出初评、教师终裁」的现实依据。

已知局限：

- 对高水平报告的区分度有限：9 份中有 4~5 份得分接近或达到满分，高分区区分度不足；
- 不支持图片与截图内容（无 OCR），扫描件与图片型报告会显著偏低；
- 超过 7 万字的报告仍走关键词召回，实测会低估（召回模式下所有 miss 已强制转人工）；
- 评语生成环节偶发输出格式失败，失败时自动退回规则兜底评语，评分与证据不受影响。

数字的复现方式：`tools/batch_run.py` + `tools/benchmark.py`。
**说明**：完整数据集（真实报告与人工打分）不在公开仓库中（含个人作业内容），
因此外部无法逐位复现这组数字；公开仓库提供**裁剪样例（`docs/cases/`）与打分表模板**
（`data/gold/gold_人工打分表_空白.xlsx`），可按 README 的流程在自己收集的数据上得到同口径的指标。

> **项目定位**：这是竞赛原型 / 教师辅助初评工具，**不是**可以无人监督直接发布正式成绩的自动评分系统。
> 系统只产出带证据的初评，最终成绩由教师确认；不支持图片与截图内容（无 OCR）。

## 快速开始（干净环境从零安装）

```bash
python -m venv .venv
source .venv/Scripts/activate        # Windows Git Bash；PowerShell 用 .venv\Scripts\Activate.ps1
pip install -r requirements.txt
pip install -r requirements-dev.txt  # 仅跑测试时需要
cp .env.example .env                 # 然后填入自己的 key（.env 不提交）
python tools/test_key.py             # 验证密钥与结构化输出是否可用
python -m pytest tests/ -q           # 无 key 也能跑，全部通过才算干净
streamlit run app.py                 # 打开 http://localhost:8501
```

`.env` 内容（也可直接复制 `.env.example`）：

```
LLM_API_KEY=sk-xxxx
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_MODEL=deepseek-chat
DEMO_MODE=false
```

`DEMO_MODE=true` 时**真的不会**调用模型（代码层拦截，不只是界面提示）；
需要离线演示请先 `python tools/make_demo.py` 生成演示结果。

## 批量测试（界面第 ⑤ 个标签页）

两种批量能力，都可以导出 CSV 留痕：

- **多份报告批量评阅**：一次跑完选中的报告，出横向对比表；
  本地存在封存的人工 `gold.json` 时，自动对齐算出 MAE / 误差≤5 分占比 / 证据可溯源率。
- **同一份报告重复评阅**：连跑 N 次，看总分极差与评分点判定稳定率 ——
  这是「G 一致性守卫」存在的实证，稳不稳用数据说话。

> 注：自定义评分点与人工 gold 的维度对不上，此时界面会**拒绝计算 MAE**，
> 因为维度不一致时算出来的误差没有意义。

## 隐私与数据说明

- 本仓库**不包含**任何原始实验报告。`data/` 目录已在 `.gitignore` 中，原始文件只保留在本地。
- 主页 `docs/cases/` 中的演示案例做了双重处理：**全文脱敏**（学号 / 姓名 / 班级 / 电话 / 邮箱均替换为占位符并做残留扫描）
  + **裁剪为证据片段窗口**（每条证据前后各保留 500 字），不含完整作业原文。
- 脱敏脚本本身**不包含任何真实姓名与本机路径**：样本清单与已知姓名从本机配置文件读取，
  该配置已在 `.gitignore` 中（仓库内只提供模板）。
- 上传的报告写入受控临时目录（UUID 文件名，不参与任何路径拼接），解析结束即在 `finally` 中删除；
  结果文件名使用随机 ID，上传文件不会长期留存。
- **原始版面对照**：PDF 报告会在页面内渲染出原始页面图（最多前 20 页，只在内存中、不落盘），
  方便教师在界面里直接核对截图、图表与公式。该功能**不做 OCR**：
  图片内容依然"看得见、读不到"，不参与自动判定，也不会成为评分依据。
