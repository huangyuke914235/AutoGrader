# 界面汉化：右上角 Deploy / 三点菜单 / 设置对话框

日期：2026-09-24
涉及文件：`chrome_i18n.py`（新增）、`static/i18n.html`（生成物）、`app.py`

---

## 一、问题

右上角「Deploy」按钮、三点菜单、设置对话框显示英文。
这些字符串是 **Streamlit 框架内部渲染**的，不在我们的 Python 源码里，
没有官方配置项可改。

## 二、方案

注入一段 JS 到宿主页面，用 `MutationObserver` 持续监听 DOM，
把出现的英文短语替换为中文。注入通道是：

**`components.v1.iframe()` 指向本应用自己的静态页面**（`static/i18n.html`）——
同源（同 host 同端口），真实 HTML 页面，`<script>` 必然执行，
iframe 内可以直接读写 `parent.document`。

`i18n.html` 由 `chrome_i18n._ensure_page()` 在启动时生成，
翻译表（`TEXT_MAP` / `PREFIX_MAP`）是唯一真源，加新短语只改这里。

### 开关已固化进配置文件（不用再加命令行参数）

`.streamlit/config.toml`：

```toml
[server]
enableStaticServing = true
```

早期是靠 `streamlit run app.py --server.enableStaticServing=true` 打开的，
但 **Streamlit Community Cloud 只允许改仓库文件、不能加命令行参数**，
所以改成写在配置里，本地和云端都生效。

**如果哪天汉化失效了**，先查这个开关：iframe 404 → 汉化静默失效，
主体功能不受影响 —— 这是有意设计的降级，但也意味着没人会发现。
用 `tools/verify_i18n.py` 在真实浏览器里验证。

## 三、四条死路的排查记录（都实测过，别再试）

| 通道 | 结果 | 原因 |
|---|---|---|
| `components.v1.html`（iframe srcdoc） | ✗ | iframe 能读 `parent.document`、手动 eval 也能翻译成功，**唯独 srcdoc 里的 `<script>` 不执行** |
| `st.markdown` 里的 `<script>` | ✗ | React 用 innerHTML 插入，浏览器不执行其中的 script 标签 |
| `st.markdown` 里的 `<img onerror>` | ✗ | 当前版本 Streamlit 的 markdown 渲染器**把整个 img 元素剥离**，页面上根本找不到它 |
| `st.iframe`（新 API，曾被弃用警告引过去） | ✗ | 见下方专节：**函数存在、签名兼容，但换完汉化直接失效** |

### 特别提醒：不要因为弃用警告就把 `components.iframe` 换成 `st.iframe`

Streamlit 1.64 会对 `components.v1.iframe` 打警告：

```
`st.components.v1.iframe` will be removed after 2026-06-01.
Please replace `st.components.v1.iframe` with `st.iframe`.
```

2026-09-24 顺着这个警告换过去，实测结果：

- `st.iframe` **确实存在**，签名兼容（`width` / `height` 都接受 `int`），调用不报错
- 但页面上的翻译**全部失效**：工具栏变回 `Deploy`、菜单变回 `Clear cache / Auto rerun / Record screen`
- `tools/verify_i18n.py` 立刻抓到（这正是它存在的意义）

推断是新 API 给 iframe 加了 `sandbox`，脚本不再执行，翻译逻辑跑不起来。
**结论：继续用 `components.v1.iframe`。** 若将来旧 API 真被移除，要重新验证的核心问题是
「新 iframe 是否还允许同源脚本执行」，而不是照警告改完就走。

## 四、一个运维坑：改完必须重启，不能靠热重载

Streamlit 的 rerun **不会重新 import 已加载的模块**（`sys.modules` 缓存）。
改 `chrome_i18n.py` 后，老进程里的旧模块会照旧生成旧版 `i18n.html` 并**覆盖**新文件
—— 现象是"我明明改了翻译表但没生效"。

**改 `chrome_i18n.py` 后必须重启服务进程。**

## 五、翻译表的两种匹配

1. **精确匹配**（`TEXT_MAP`）：整段文字完全一致才替换，防止误伤报告正文。
2. **前缀匹配**（`PREFIX_MAP`）：文字**以某前缀开头**时替换前缀。
   用在带版本号等变动部分的场景 —— 菜单底部的版本行实际是
   `Made with Streamlit v1.64.0`，精确匹配永远命不中。

替换后文本不再以该前缀开头，天然幂等，observer 不会死循环。

## 六、验证

```bash
python tools/verify_i18n.py        # 默认 http://localhost:8502，AG_URL 可覆盖
```

真实浏览器（Playwright）检查三点：右上角工具栏、三点菜单（实际点开）、页脚。
输出截图 `tools/_i18n_check.png` 供人工复核。

为什么必须真实浏览器：汉化脚本注入在 iframe 里，AppTest 不执行 iframe，
这件事**只能在真实浏览器里验**。

当前状态（v1.64.0）：工具栏「部署」、菜单项（跟随系统 / 浅色 / 深色 /
重新运行 / 自动重跑 / 清除缓存 / 打印 / 录制屏幕）、版本行全部中文。

## 七、已知边界

- **Streamlit 升级可能换文案**（如把 `Record screen` 改回 `Record a screencast`）。
  翻译表按当前 v1.64.0 的实际文案写的；升级后跑 `verify_i18n.py`，
  红了就往 `TEXT_MAP` 里补新文案（旧的留着无害）。
- 菜单项的快捷键提示（如 `重新运行 R` 里的 R）是独立节点，不翻译。
- 按钮的 `title` 悬浮提示（如版本行的 `Copy version`）在属性里不在文本节点里，
  未翻译，影响极小。
